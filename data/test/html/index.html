Every page renders its assertions into the page itself and mirrors them to the kernel log as TEST PASS name / TEST FAIL name, so a run can be checked visually or with grep TEST build/qemu_xbrowser.log. Each page also prints one TEST <PAGE>-SUMMARY pass=N fail=N line at the end.

make browser in system/platform builds browser/ and then copies browser/data into the staging rootfs, so this directory lands on the target image at /data/test/html/ and the hub opens as file:///data/test/html/index.html. file:// is resolved by stripping the scheme and reading the rest with vfs_readfile. The pages have to be re-copied after an edit - the staging step is a plain cp -r, not a build rule - and then repacked with make final && make sd. Serving the directory over HTTP works too, and is the only way to exercise fetch/XMLHttpRequest against a real response - this widget wires no http_request hook, so both report a network error here.

Pages must be self-contained: the loader drops <script src=...> rather than fetching it, so an external script never runs.
